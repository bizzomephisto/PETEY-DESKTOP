# PETEY coding-agent context

Scope: repository. Snapshot: 2026-09-23, stable release v0.19.0; retained experimental preview v0.19.0-experimental.1.
Start here; read only task-relevant implementation/tests. This is a navigation cache, not a substitute for checking code before edits. Source wins on factual drift; update this file when architecture, commands, contracts, or extension points change. Keep it compact; no session logs or copied source.

## Fast start

- Product: standalone desktop AI companion/roleplay assistant; chats, personas, SQLite memory/RAG, media studio/gallery, voice, visual mode, and optional integrations.
- Stack: Python 3.12+, Flask/Werkzeug, pywebview, vanilla JS/CSS/HTML; direct HTTP provider clients. No JS build pipeline/package.json.
- Launch: `python run_desktop.py`; browser development: `python run_desktop.py --browser`; trusted phone/mic: `python run_desktop.py --lan-https`; existing named-tunnel access: `python run_desktop.py --cloudflare` with `PETEY_CLOUDFLARE_HOSTNAME` and `PETEY_CLOUDFLARE_PORT`; Linux menu shortcut: `python run_desktop.py --install-shortcut`; cursor popup: `python run_desktop.py --quick`; COSMIC Super+F1 binding: `python run_desktop.py --install-quick-hotkey`.
- The visible app/window/launcher name is `PETEY`. Linux Qt windows retain `petey-desktop` as their application name and desktop-file ID; keep the installed launcher's `StartupWMClass` aligned so docks resolve the icon on Wayland/X11.
- `--install-shortcut --cloudflare --cloudflare-hostname <host>` saves the resolved hostname and port in the launcher command.
- The native Restart PETEY bridge can restart in the current, desktop, Cloudflare, or browser mode. A successful Cloudflare launch persists its hostname and port in private `remote-access.json`; later desktop launches reuse them, and the restart flow prompts when none is saved. It does not rerun one-shot shortcut installation or pairing-token rotation.
- The native desktop restores its last normal width and height from `desktop-window.json` in the data root. Debounced resize events update it atomically; fullscreen and maximized dimensions are ignored.
- Setup: venv + `python -m pip install -r requirements.txt`; copy `.env.example` only if `.env` absent. Linux requirements select pywebview/PySide6; FFmpeg supplies video previews. See README for platform setup.
- First checks: `git status --short`; `git ls-files`. Use `rg -n 'symbol' specific/files` then bounded reads. Avoid dumping entire large files, repository-wide recursive reads, assets, environments, databases.
- This folder (`PETEY_DESKTOP`) contains the standalone desktop project. Legacy Discord/web-admin source, data, and the old copied `venv` have been removed; `.gitignore` still excludes them to prevent accidental reintroduction. Use `.venv` for the desktop environment and tracked files to identify current source.

## Runtime/data flow

Model control is opt-in per compatible add-on. Persistent policy lives in `DesktopState.settings.petey_control`, defaults off, and covers individual capabilities plus Desktop, Mobile, Discord, and Petey Life surfaces. Metered capabilities have autonomous daily limits; `ToolSpec.explicit_when` lets a direct user request bypass only that limit. `AddonManager.tool_specs(surface=...)` wraps both schema availability and dispatch authorization. Desktop filesystem MCP and unrelated core tools are never included by an add-on grant.

`ToolSpec.required_when` lets a narrowly gated capability require one initial tool call. When a direct request matches one or more required tools, `ToolRegistry.schemas_for()` excludes unrelated autonomous tools so provider required/ANY mode cannot choose the wrong action. `ToolRegistry.requires_tool()` passes that decision through desktop and Discord conversations; provider loops use required/ANY only on the first round and return to automatic selection afterward so the model can produce its final answer.

`run_desktop.LocalServer` -> `create_desktop_app()` -> threaded Werkzeug on loopback -> pywebview (or browser). Explicit `--lan` mode binds `0.0.0.0:8765`, prints a random private-link token, and exchanges it for an HttpOnly SameSite cookie. `--lan-https` creates/reuses a private CA under the data root's `lan-tls/`, issues a fresh LAN-IP server certificate with OpenSSL, offers the public CA through a token-gated first-run HTTP installer, then serves the same token-gated app with a Secure cookie over HTTPS. `--cloudflare` opens the normal desktop window while mirroring its configured fixed origin port on IPv4 `127.0.0.1` and IPv6 `::1`, so a named tunnel using `localhost` can reach either resolution. It loads or creates a durable pairing secret in private `remote-access.json`, prints the tokenized HTTPS link, and exchanges it for a one-year HttpOnly SameSite Secure cookie; the bare hostname returns 401 even if Cloudflare Access is absent or misconfigured. `--rotate-mobile-access` replaces the secret and invalidates paired browsers. Cloudflare Access remains an outer authentication layer; PETEY does not start or configure `cloudflared`. Normal startup remains loopback-only. At widths up to 760px the UI exposes chat, visual mode, a collapsible PETEY action dock, and an essentials-first settings sheet. Show all settings opens the complete settings views with a direct return to chat. Mobile chat keeps attachment and push-to-talk visible; a quick mic tap toggles the persisted microphone mute while holding records and releasing submits. The browser-local mobile voice method can override an enabled desktop voice mode; Push to talk keeps the phone microphone closed while idle without changing the desktop's saved mode. Visual fullscreen remains a direct overlay control. Microphone mute persists through `voice_input.muted`, speaker mute persists through `speech.auto_speak`, and chat/Visual Mode on desktop and mobile restore those shared values. Mobile answers use one automatic speech request, and queued replies, add-on announcements, and wake acknowledgements re-check the current mute state before playback. Core CSS/JS URLs carry a startup mtime revision so browsers and tunnel caches pick up interface changes after restart. `DesktopBridge` handles native folder dialogs, window flags/fullscreen, gallery open/save, project/provider links, and native Save As for files restricted to an add-on's own `addon-data/` directory.

UI `web/templates/desktop.html` + `web/static/desktop.js` + `desktop.css` -> `/api/desktop/*` in `web/desktop_app.py` (composition root, validation, errors, service injection). `/api/desktop/bootstrap` includes initial chat messages and voice-cue metadata; revisioned core assets are immutable-cached. `window.peteyMediaDevices` coordinates browser-local camera/microphone leases for add-ons, `window.peteyConferenceAudio` temporarily yields/restores core continuous voice capture for a recording add-on, and `window.peteyAudioControls.speakerEnabled()` lets add-on cues obey global speaker mute. PETEY Webcam v0.3 exposes stable named sources and relays remote Conference record/frame commands; Conference v0.3 can keep its microphone/controller on mobile while a named desktop camera uploads video, stores both originals, and uses FFmpeg for a best-effort combined recording without silent camera fallback. Conference v0.3 also runs local wake detection while it owns the mic, cuts live transcription on post-speech silence, asks permission before keyword-triggered contributions, recognizes common yes/no replies, and opens a three-second follow-up window after PETEY speaks. Every supported audio file under `voice-cues/<voice>/conference/permission/` is a random permission option; its filename supplies the transcript text.

Desktop preferences include `interface_layout`: `classic` keeps the Companion shell and `command` enables the three-column Command Center with a live session rail. Mobile ignores this choice. Add-on scripts may register bounded rail actions and transient notifications through `window.peteyInterface`; calls made before `desktop.js` loads are queued by the template shim.

The desktop chat header keeps the conversation title and runtime status visible. Its chevron dropdown owns the profile, visual animation, fullscreen, Chat/Visual, and Temporary controls; it closes after a selection, outside click, or Escape. The version sits beneath the GitHub and deAPI links in the desktop sidebar footer. Mobile continues to use its separate compact controls.

Visual Mode renders six distinct, full-canvas reactive scenes on pure black: `neural_core`, `synapse_drift`, `orbital_mind`, `signal_bloom`, `aurora_flow`, and `constellation_field`. All styles derive orange listening, violet/blue thinking, blue speaking, muted, and error states from live chat/microphone/speech state; speech and microphone RMS drive motion, scale, light, signals, and particles. Mobile captions remain in the upper third; desktop fullscreen captions sit directly below the state heading. Mobile keeps fixed mic/push-to-talk/speaker controls above PETEY at the bottom. The persisted microphone mute stops recording/listening across desktop and mobile; muted mic and speaker buttons show a red X. The frameless PETEY avatar button toggles a bottom action row with Chat on the left and Fullscreen/Settings on the right.

Add-on panel JavaScript and stylesheets use a revision from their own file mtimes in rendered asset URLs; changing external add-on assets refreshes mobile/tunnel caches independently of core CSS/JS.

Published add-on replies retain their requested `petey_desktop` or `mobile_petey` surface. Event polling advances globally but renders and speaks a live event only on matching clients; the persisted reply remains in shared chat history. Include surface in deduplication so the same direct action from desktop and mobile remains distinct.

Updates are explicit user actions. `PeteyUpdater` in `updater.py` permits PETEY core only as a clean fast-forward from official main. Add-ons opt in with a manifest `repository` pointing to GitHub; install accepts a bounded ZIP asset from the latest release only after validating its paths, ID, version, and manifest, replaces code atomically, preserves `addon-data/<id>`, and requires restart. API: `/api/desktop/updates*`; UI: the Updates card in `view-addons`.

Chat feed external links and remote-media open actions use `DesktopBridge.open_external_url` for HTTP(S) handoff to the OS default browser with a new-window request. Locally saved generated media, including chat links, use `DesktopBridge.open_gallery_item` and the OS media viewer. Browser/mobile sessions use `_blank` links on the current origin. OpenCode artifact and gallery URLs emitted as loopback Markdown are normalized to paths before storage and on rendering so remote sessions retain their paired host and cookie. OpenCode artifacts open in a sandboxed full-window preview with Close and Open in browser controls; Cloudflare desktop pop-out uses `DesktopBridge.open_petey_artifact` to pair the external browser against the named public origin instead of exposing an unusable loopback URL.

Add-ons: `AddonManager` in `addons.py` discovers `petey-addon.json` folders under the local data root's `addons/` directory without importing disabled code. Persistent enablement is `DesktopState.settings.addons`; changes require restart. Enabled external entrypoints run `setup(AddonContext)` after core routes/database setup and may add namespaced API routes, optional sidebar panel/assets, services, model tools, opt-in hidden events through `context.emit_event()`, and a returned `close()` hook. `AddonEventBroker` serializes a bounded event queue; event prompts stay hidden while PETEY replies are saved and polled by desktop/mobile clients, requested speech respects speaker mute, and sanitized metadata may attach one HTTPS image/link to a visible reply. Successful tool results may attach one same-origin or HTTPS chat image through `chat_image_url` and optional alt/caption/link fields; persistent replies require a durable bounded source URL. Autonomous events cannot call tools; a directly clicked add-on action may pass `user_initiated=True` to retain normal surface-authorized tools while hiding the command. Assets resolve inside the add-on folder; writable state belongs in `addon-data/<id>`. Model tools are separately off by default under `settings.petey_control`; grants cover capabilities and Desktop/Mobile/Discord/Petey Life surfaces, and metered autonomous uses are counted per local day. Discord is the only built-in add-on and defaults on; deAPI Media appears as a core controllable service rather than packaged add-on code. GitHub releases do not bundle third-party/example add-ons; `scripts/package_release.py` rejects `examples/`, known legacy add-on roots, every external `petey-addon.json`, `.env`, and symlinks. UI/API: `view-addons`, `/api/desktop/addons*`; overview: `ADDONS.md`; author contract: `docs/addons.md`. Add-ons are trusted local code with process-level access.

Chat model picker: `AIProvider.list_models` supports Gemini's paginated model catalog (filtered for chat), OpenAI, and local servers. Providers settings exposes one dropdown per model; `loadModelCatalogs` automatically refreshes on settings entry, provider/key changes, and local server URL changes, preserving selections and rejecting stale replies. Catalog presence does not guarantee account access; Test connection checks generation.

Vision has no separate UI selector. With Gemini chat, `AIProvider._vision_model` follows the chat model (including older settings); saving Gemini chat also synchronizes the retained vision setting. OpenAI/local chat still uses the configured Gemini vision model. Read-only catalog provider and local `base_url` overrides never change saved settings.

Chat: multipart `/chat` -> surface-aware `AssistantIdentity` (`petey_desktop` or `mobile_petey`) + optional `AssistantAttachment` -> `AssistantService.respond` -> recent history + cross-conversation retrieval + optional Gemini image description -> `AIProvider.complete[_with_tools]` -> `AssistantReply(text,tool_events)` -> persistence/UI. Each saved conversation may reference one saved Petey profile slot; unassigned chats resolve the current system persona. The effective profile supplies the chat prompt and speech voice without replacing global persona settings. A profile-boundary system rule treats history and cross-conversation retrieval as factual context only, preventing prior replies from supplying personality or style. User messages can use deferred embeddings; queue them after provider completion. Assistant author ID = `PETEY`.

Chat streaming: multipart `/chat` with `stream=true` returns NDJSON status/delta/done/error events and heartbeats via a bounded worker queue. `AssistantService.respond(on_text=...)` uses `AIProvider.complete_stream` for ordinary replies; tool loops remain buffered. `AIProvider.complete_with_tools` supports Gemini and OpenAI-compatible function calling with duplicate-call protection. Provider SSE responses close on completion/error; only final cleaned replies enter assistant memory. JS `readChatStream` handles split UTF-8/events and marks interrupted partial replies; automatic speech can start from the first complete streamed sentence and queues the remainder. The original JSON route behavior remains available without the stream flag.

MCP tools: `FilesystemMCPManager` in `mcp_client.py` owns a persistent stdio JSON-RPC connection to a pinned official filesystem server launched through `npx`. Folders approved under Settings → Tools are its only roots. `tool_specs()` filters the discovered catalog through an explicit read-only allowlist and prefixes model-facing names with `mcp_filesystem__`; write/move/delete capabilities never enter `ToolRegistry`. Settings/API: `DesktopState.tools`, `/api/desktop/tools*`, `view-tools`, `loadTools`. First enable may download the pinned npm package; opening Settings alone never starts it. `LocalServer.close()` stops the child process.

Discord: sidebar `view-discord` -> `/api/desktop/discord*` -> injectable `DiscordBridge` worker (`discord_bridge.py`) -> official Discord v10 REST plus `DiscordGateway` presence and interactions (`discord_transport.py`). `room_chat.py` supplies bounded model context and adaptive pacing. `discord_media.py` defines guild slash commands mapped to the desktop `MediaJobManager`; interaction attachments are HTTPS Discord CDN files capped at 25 MiB, jobs use saved provider/model settings, results enter Gallery, and deferred replies are updated before the 15-minute interaction-token limit. Command registration creates/updates PETEY's known commands without deleting unrelated application commands. The OAuth invite requests Administrator (`8`) plus `applications.commands`. Connect starts Gateway Identify with online presence, heartbeat, and reconnect; close stops it. Successful connects persist the selected server/channel; optional auto-connect reuses it at app startup. `DesktopState.settings.discord.persona_slot` independently selects a saved profile for Discord; the effective prompt combines it with the editable room prompt and never reads the active chat persona. Discord default uses only the built-in room identity. `settings.discord.memory_policy` is `room_only` (no SQLite access), `store` (write Discord messages/replies so Desktop/Mobile can retrieve them), or `shared` (also retrieve cross-surface memory for public replies); default `room_only`. Stored Discord rows use `source_surface=discord` and conversation ID `discord:<guild>:<channel>`. Room prompt, persona, and memory changes apply to the next reply; AI enhance returns an unsaved room-prompt draft from the configured chat provider. Petey Life reads `DesktopState.system_prompt`, so it always uses the system-default profile. Owner instructions matching create text channel, delete selected channel, or clear 1–100 recent messages create ten-minute review proposals; `/discord/admin-approve` executes them and public channel text never does. Direct mentions/replies/name matches, a three-minute same-speaker follow-up window, and persistent watched topics bypass warm-up and the Discord message ceiling, with a two-second eligibility cap. Persistent pacing modes govern only spontaneous participation. Native typing starts before generation and refreshes every 8s. REST poll interval 4s. Ignores bots/webhooks and disables outgoing mentions. Bot token stays private with `DISCORD_BOT_TOKEN` fallback. Model snapshot at Connect; add-on tools require separate explicit grants. UI: `web/static/discord.js`, `web/templates/desktop_discord.html`; tests `test_discord*.py` and `test_room_chat.py`, API coverage in `test_desktop_app.py`. See `docs/discord.md`.

Media: route or model tool -> `MediaJobManager.submit` -> worker -> `MediaService` -> async `DeapiClient` -> progress/job polling -> `MediaGallery` capture. Default 3 workers; queued does not mean completed. Chat speech may use transient job audio outside gallery.

Media estimates: `/media/estimate` -> `MediaService.estimate` -> `DeapiClient.estimate_price` uses deAPI v2 price lookups without queuing jobs. Images/video share model parameter limits with generation; speech, music, and legacy video restyling have no estimate. JS `scheduleMediaEstimate` debounces lookups and rejects stale replies. Catalog, balance, and estimate requests use request-local clients via `media_provider_request` to isolate event loops.

State: `DesktopState` owns installation/person IDs, conversation metadata including nullable `persona_slot`, settings, personas/voice slots, and approved Filesystem folders. `conversation_persona`, `conversation_system_prompt`, and `conversation_speech` resolve the effective profile with system fallback. JSON writes use temp-file replacement + lock. `DesktopMemory` owns message/document content and embeddings; SQLite WAL, per-operation connections, bounded background embedding workers. Tables: `memory_items`, `image_generations`, `metadata`; message rows include validated `source_surface` plus `metadata_json` for durable UI data such as chat tool events, and existing databases migrate both fields safely. Retrieval labels sources and orders selected results oldest-to-newest so explicit recent corrections win while older entries remain auditable. Deleting a chat either clears its message rows or preserves them as searchable orphaned memory, based on the explicit UI choice. Embedding provider/model/dimension signatures matter.

Data root: `PETEY_DATA_DIR` override; else Linux `$XDG_DATA_HOME/petey` or `~/.local/share/petey`; macOS `~/Library/Application Support/Petey`; Windows `%LOCALAPPDATA%/Petey`. Files: `installation.json`, `settings.json`, private `remote-access.json`, `petey-memory-v2.sqlite3`, `gallery/`, and user-managed `voice-cues/<speech voice>/` acknowledgement clips with `voice-cues/default/` fallback. Conference permission clips live one level deeper at `voice-cues/<speech voice>/conference/permission/`, also with the `default` voice fallback. Never use real user data for tests or commit it. `.env`, `envbak/`, `config_*.json`, `chroma_db/`, `gens/`, `user_images/` are private/ignored; don't read secrets for onboarding.

## Preserve these contracts

Help: sidebar `view-help` includes `web/templates/desktop_help.html`; setup links and feature guidance stay here, with settings jumps through `data-settings-view` / `data-settings-target`. Keep `knownViews` aware of `help` for direct `#help` navigation. Provider documentation links open externally.

- Temporary chat bypasses memory reads/writes and image-generation memory recording; temporary history is supplied by frontend. It can still invoke providers/tools; it is not offline mode.
- Chat, vision, embeddings, TTS, STT have separate configuration. Vision is Gemini even when chat is OpenAI/local. STT defaults to deAPI with Gemini fallback. Conversational TTS supports explicit deAPI, Gemini, and OpenAI choices; Automatic streams Gemini first and falls back to OpenAI. Inspect each path before changing fallback behavior.
- Public provider settings must redact keys. Environment names: `GEMINI_API_KEY`, `OPENAI_API_KEY`, `LOCAL_AI_API_KEY`, `DEAPI_KEY`. Use `.env.example` for names, not `.env` contents.
- Tool availability is checked both when offering schemas and dispatching. Current conversational tool is `generate_image`, gated by explicit image intent; keep paid actions tied to user intent. Validate arguments in handlers.
- Filesystem MCP receives only folders explicitly approved under Settings → Tools. Keep the model-facing allowlist read-only and bounded; never pass through server write, move, delete, or arbitrary command tools. Enabling the connector must be an explicit user action.
- Disabled user add-ons must not be imported. Add-on enable/disable remains restart-gated; external paths and served assets stay inside the discovered folder. Register core routes before external `setup()`, keep add-on endpoints under `/api/addons/<id>/`, and close add-ons before shared runtimes/workers.
- Wake-name mode acknowledges only a standalone wake name followed by a short pause. Continued speech cancels the pending cue, so commands beginning with “Petey” are not interrupted. Preserve the local-detector fast path, immediate local-chime fallback, optional browser-spoken fallback, transcription fallback, speech-overlap guard, per-voice cue lookup, and cache-busted clip URLs together.
- A standalone wake starts a voice-conversation session. `markVoiceConversationRequest` suppresses recording while the model/TTS responds; `openVoiceConversationFollowup` re-arms wake-free follow-ups for `voice_input.follow_up_seconds` (3–30, default 8) after the final speech segment. Completed utterances are uploaded to the selected transcription provider. This same browser flow serves desktop and HTTPS mobile access.
- `AsyncRuntime.call` uses a fresh event loop per request and closes the shared deAPI session. Media model/balance reads must create and close a request-local client for both saved and environment keys: the first Media visit requests them concurrently. Preserve session/loop ownership and job-worker shutdown; don't casually move blocking/provider calls between threads/loops.
- Keep Flask loopback-only by default. Network binding must remain explicit and token-gated; never print an unprotected LAN URL. Upload cap currently 25 MiB. Preserve API error handling and bounded inputs.

## Extend + validate

- New setting: state default/load/validation/update -> API public projection -> HTML/JS -> state/API tests; existing settings must still load.
- New feature: relevant service -> route -> UI as needed; reuse injectable services and existing boundaries. New media operation must cover catalog, input validation, dispatch, job handling/UI, tests.
- Full suite: `python -m unittest discover -s tests -v`.
- Focused suite example: `python -m unittest discover -s tests -p 'test_mcp_client.py' -v` (substitute mapped test filename). Tests use `unittest`, mocks/AsyncMock, temporary directories, Flask test client; do not require paid live calls for routine verification.

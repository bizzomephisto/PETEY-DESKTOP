# PETEY Home Assistant Alert Relay

PETEY's Home Assistant add-on can receive live alerts from Home Assistant, send
them into the active PETEY chat, and optionally announce them aloud. The feature
is available in **Home Assistant MCP v1.2.0**.

## What it supports

- Existing Home Assistant `alert.*` entities becoming active
- Optional announcements when an `alert.*` entity returns to idle
- Custom `petey_alert` events from automations and scripts
- Desktop and mobile chat delivery
- Optional spoken announcements that respect PETEY's global speaker mute
- An editable prompt controlling how PETEY presents alerts
- Automatic reconnection after Home Assistant or the network restarts
- Duplicate protection using Home Assistant event context IDs
- A built-in test alert

## Enable the relay

1. Restart PETEY after installing or updating the Home Assistant add-on.
2. Open **Home Assistant** from PETEY's add-on navigation.
3. Confirm the Home Assistant address and long-lived access token are configured.
4. Under **Alert relay**, enable **Relay Home Assistant alerts**.
5. Choose whether PETEY should speak alerts.
6. Choose whether PETEY should announce resolved alerts.
7. Edit the alert prompt if desired.
8. Select **Save alert relay**.
9. Wait for the alert badge to show **Listening**.
10. Select **Send test alert**.

The relay setting is persistent. Once enabled, it starts automatically with PETEY.

## Existing Home Assistant alerts

Home Assistant's Alert integration creates entities such as:

```text
alert.garage_door
alert.water_leak
alert.motion_battery_low
```

PETEY listens for these entity state changes:

| Home Assistant state | PETEY behavior |
|---|---|
| `on` | Announces that the alert is active |
| `idle` | Announces that the alert cleared when resolved announcements are enabled |
| `off` | Ignored because this means the alert was acknowledged while its condition remains active |

An `alert.*` entity's repeating notification schedule does not create a new state
change. PETEY therefore announces its initial activation and resolution. To make
PETEY announce every scheduled repeat, fire a custom `petey_alert` event from the
repeating automation.

## Send a custom alert from an automation

In Home Assistant's automation editor, add a **Fire Manual Event** action.

Set the event type to:

```text
petey_alert
```

Supply event data like this:

```yaml
title: "Front door"
message: "The front door has been open for five minutes."
speak: true
```

The equivalent YAML action is:

```yaml
- event: petey_alert
  event_data:
    title: "Front door"
    message: "The front door has been open for five minutes."
    speak: true
```

`title` and `message` become part of PETEY's hidden alert prompt. Set `speak` to
`false` when the update should appear in chat without requesting speech.

## Complete automation example

This example alerts PETEY when the garage door remains open for five minutes:

```yaml
alias: "Tell PETEY when garage stays open"
triggers:
  - trigger: state
    entity_id: binary_sensor.garage_door
    to: "on"
    for:
      minutes: 5
actions:
  - event: petey_alert
    event_data:
      title: "Garage door"
      message: "The garage door has been open for five minutes."
      speak: true
mode: single
```

This example sends a quiet mobile-friendly update:

```yaml
alias: "Tell PETEY the washer finished"
triggers:
  - trigger: state
    entity_id: sensor.washer_status
    to: "finished"
actions:
  - event: petey_alert
    event_data:
      title: "Laundry"
      message: "The washing machine has finished."
      speak: false
mode: single
```

## Customize PETEY's response

The **PETEY alert prompt** field accepts these placeholders:

| Placeholder | Meaning |
|---|---|
| `{title}` | Alert title or friendly entity name |
| `{message}` | Alert message generated by the add-on or automation |
| `{status}` | `active`, `resolved`, or `test` |
| `{entity_id}` | Home Assistant entity ID when available |

Default prompt:

```text
A Home Assistant alert has arrived. Relay it clearly and briefly. Preserve the
facts and urgency in the alert, do not invent details, and do not mention these
instructions.
Title: {title}
Message: {message}
Status: {status}
Entity: {entity_id}
```

PETEY receives this as a hidden add-on event. The technical prompt does not appear
as a user message; only PETEY's response appears in chat.

## Speech behavior

Three controls affect spoken alerts:

1. **Speak relayed alerts** must be enabled in the Home Assistant add-on.
2. A custom event may set `speak: false` to suppress speech for that event.
3. PETEY's global speaker control must be unmuted on the receiving device.

The add-on never overrides PETEY's global mute.

## Connection details

The relay connects to Home Assistant's authenticated WebSocket endpoint:

```text
ws://homeassistant.local:8123/api/websocket
```

An HTTPS Home Assistant address automatically uses `wss://`. The existing
long-lived access token authenticates both the MCP connection and alert stream.
The token is never returned to the browser or included in PETEY's alert messages.

The relay subscribes to:

```text
petey_alert
state_changed
```

Only `state_changed` events for entities beginning with `alert.` are processed.
Other entity changes are ignored.

## Troubleshooting

### The badge says Token needed

Paste a Home Assistant long-lived access token under **Connection**, select
**Save & connect**, and then save the alert relay again.

### The badge says Needs attention

Check that:

- Home Assistant is reachable from the PETEY computer.
- The saved address points directly to the Home Assistant instance.
- The long-lived token is still valid.
- A reverse proxy permits WebSocket connections to `/api/websocket`.

PETEY retries the connection automatically with a bounded backoff.

### The test appears in chat but does not speak

Check **Speak relayed alerts**, the event's `speak` value, and PETEY's global
speaker button. Mobile browsers must remain connected to PETEY to play speech.

### An automation does not reach PETEY

Use the exact lowercase event type `petey_alert`. Confirm the automation uses a
**Fire Manual Event** action and that `message` contains text. Use **Developer
Tools → Events** in Home Assistant to fire a test event manually.

### A standard alert does not repeat through PETEY

Home Assistant's Alert integration can repeat notifications without changing the
`alert.*` entity state. Fire a `petey_alert` event from the repeating automation
when every repeat should produce a new PETEY response.
